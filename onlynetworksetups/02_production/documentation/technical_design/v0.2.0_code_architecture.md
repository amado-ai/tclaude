## 1. Architecture Overview

V0.2.0 establishes three foundational systems that all future missions will build on:

```
┌─────────────────────────────────────────────────────────┐
│                    INPUT / PLAYER                        │
│   FirstPersonController → InteractionRaycaster           │
└────────────────────┬────────────────────────────────────┘
                     │ IInteractable.OnPickup / OnInspect
┌────────────────────▼────────────────────────────────────┐
│                INTERACTION LAYER                         │
│   ObjectHolder  │  CableConnector  │  PortReceiver       │
└────────────────────┬────────────────────────────────────┘
                     │ CableConnectedEvent / PortConnectedEvent
┌────────────────────▼────────────────────────────────────┐
│              NETWORKING LOGIC LAYER                      │
│   DeviceStateMachine  │  LEDController  │  EventBus      │
└────────────────────┬────────────────────────────────────┘
                     │ DeviceStateChangedEvent
┌────────────────────▼────────────────────────────────────┐
│               MISSION SYSTEM LAYER                       │
│   MissionValidator  │  FeedbackManager  │  UIController  │
└─────────────────────────────────────────────────────────┘
```

Each layer communicates **downward via method calls** and **upward via events**. No layer imports from a layer above it. This keeps the prototype extensible into full mission system territory (V0.4.0) without refactoring.

## 2. System Modules

### 2.1 Interaction Layer (`02_production/game_build/interaction/`)

#### InteractionRaycaster
- Fires a single physics raycast from the camera center, 20 times/second when idle, every frame when holding an object (cable tip tracking).
- Detects `IInteractable` interface on hit collider's component tree.
- Delegates to `ObjectHolder` for pickup and `PortReceiver` for connection.

#### ObjectHolder
- Manages one held object at a time.
- Held object follows `Camera.forward * holdDistance + Camera.position` with `Vector3.Lerp` smoothing (factor 12/frame).
- Inspect mode: disables position tracking; maps mouse/touch delta to object rotation around its center pivot.
- Releases object on secondary action or when a connection is confirmed.

#### IInteractable (Interface)
```csharp
public interface IInteractable
{
    string DisplayName { get; }
    void OnHoverEnter();
    void OnHoverExit();
    void OnPickup(ObjectHolder holder);
    void OnInspect();
    void OnRelease();
}
```

#### CableConnector
- Owns two `CableEnd` child objects (one per plug).
- Each `CableEnd` has a trigger collider that fires `OnTriggerEnter` when overlapping a `PortReceiver`.
- Connection requires: correct type match + port unoccupied + player confirm input.
- On confirm: calls `PortReceiver.Register()`, publishes `CableConnectedEvent`, disables held-object physics.

#### Cable Types (Enum)
```csharp
public enum CableType { Coax, Ethernet, PowerBarrel }
```

#### Port IDs (Enum)

### 2.2 Networking Logic Layer (`02_production/game_build/networking_logic/`)

#### DeviceStateMachine

Implements the modem and router state machines as described in FT-001. Responds to events from `PortReceiver` via `EventBus`. Does not reference `CableConnector` directly.

**Device States (Enum)**
```csharp
public enum DeviceState
{
    Off,
    Booting,
    DsUsSync,   // Modem only
    Online,     // Modem only
    WanActive,  // Router only
    WifiBroadcasting  // Router only
}
```

**Full Modem State Diagram**
```
OFF ──[Power-IN connected]──► BOOTING (3 s)
         └──[Coax-IN already connected OR connected during boot]
              ──[boot complete]──► DS_US_SYNC (5 s)
                   ──[sync complete]──► ONLINE
                        └──[any required port removed]──► OFF
```

**Full Router State Diagram**
```
OFF ──[Power-IN connected]──► BOOTING (2 s)
         └──[boot complete + WAN-IN occupied + modem==ONLINE]──► WAN_ACTIVE
              ──[immediately]──► WIFI_BROADCASTING
                   └──[WAN-IN or Power-IN removed]──► OFF
```

**Event subscriptions**
```csharp
void Awake()
{
    EventBus.Subscribe<CableConnectedEvent>(OnCableConnected);
    EventBus.Subscribe<CableDisconnectedEvent>(OnCableDisconnected);
    EventBus.Subscribe<DeviceStateChangedEvent>(OnOtherDeviceStateChanged);
}
```

#### LEDController
- Holds a serialized array of `LEDGroup` objects (one per LED strip segment).
- Called by `DeviceStateMachine.TransitionTo()` with the new state.
- Sets `MeshRenderer.material.color` or `EmissionColor` per LED based on a `LEDStateConfig` ScriptableObject.
- Supports: off, amber-solid, amber-blink (coroutine), green-solid.

**LEDStateConfig (ScriptableObject)**
```csharp
[CreateAssetMenu(menuName = "onlynetworksetups/LEDStateConfig")]
public class LEDStateConfig : ScriptableObject
{
    public DeviceType deviceType;
    public DeviceState state;
    public LEDGroupConfig[] groups;
}

[System.Serializable]
public struct LEDGroupConfig
{
    public string groupName;
    public Color color;
    public bool blink;
    public float blinkRate;
}
```

#### EventBus
Lightweight static pub/sub. No MonoBehaviour dependency. Type-safe via generics.

```csharp
public static class EventBus
{
    private static readonly Dictionary<Type, List<Delegate>> handlers = new();

    public static void Subscribe<T>(Action<T> handler)
    {
        var key = typeof(T);
        if (!handlers.ContainsKey(key)) handlers[key] = new();
        handlers[key].Add(handler);
    }

    public static void Publish<T>(T evt)
    {
        if (!handlers.TryGetValue(typeof(T), out var list)) return;
        foreach (var h in list) ((Action<T>)h)(evt);
    }

    public static void Unsubscribe<T>(Action<T> handler)
    {
        if (handlers.TryGetValue(typeof(T), out var list))
            list.Remove(handler);
    }
}
```

**Events**
```csharp
public record CableConnectedEvent(CableConnector Cable, CableEnd End, PortReceiver Port);
public record CableDisconnectedEvent(CableConnector Cable, CableEnd End, PortReceiver Port);
public record DeviceStateChangedEvent(DeviceType Device, DeviceState NewState);
public record MissionCompleteEvent(string MissionID, float ElapsedSeconds);
```

### 2.3 Mission System Layer (`02_production/game_build/mission_system/`)

#### MissionValidator
- Subscribes to `DeviceStateChangedEvent`.
- For the V0.2.0 prototype: success condition = `router.State == DeviceState.WifiBroadcasting`.
- On success: publishes `MissionCompleteEvent`, triggers `UIController.ShowSuccessScreen()`.
- Fires success exactly once (guarded by `bool completed`).

```csharp
public class MissionValidator : MonoBehaviour
{
    private bool completed = false;

    void Awake()
    {
        EventBus.Subscribe<DeviceStateChangedEvent>(OnDeviceStateChanged);
    }

    void OnDeviceStateChanged(DeviceStateChangedEvent e)
    {
        if (completed) return;
        if (e.Device == DeviceType.Router && e.NewState == DeviceState.WifiBroadcasting)
        {
            completed = true;
            EventBus.Publish(new MissionCompleteEvent("prototype_room", Time.time));
            UIController.Instance.ShowSuccessScreen();
        }
    }
}
```

#### FeedbackManager
- Static helper called by `CableConnector` and `DeviceStateMachine`.
- `PlaySnap()` — short positive audio + haptic (0.1 s light impact).
- `PlayError()` — short negative audio + haptic (0.05 s rigid impact).
- `PlayBootBeep()` — device boot audio cue.
- Platform-specific haptic calls abstracted behind `HapticProvider` interface with iOS/Android/NoOp implementations.

| Metric | Target |
|---|---|
| Frame rate | 60 FPS on mid-range 2022 Android (Snapdragon 778G) |
| Raycast budget | Max 1 physics raycast per 50 ms when idle |
| LED coroutines | Max 4 concurrent blink coroutines |

## 7. Exit Criteria (V0.2.0)

1. Player can enter the prototype room.
2. Player can pick up, inspect, and release all six cable/adapter objects.
3. Connecting correct cable to correct port latches and triggers device state progression.
4. Connecting wrong cable type to a port plays error feedback and does not latch.
5. Modem LED sequence (Off → Booting → DS/US Sync → Online) is visible.
6. Router LED sequence (Off → Booting → WAN Active → Wi-Fi Broadcasting) is visible.
7. Success screen appears exactly once.
8. 60 FPS maintained on target device throughout interaction.
9. No null reference exceptions or crashes in any pass/fail path.
